# Canonical Circuit Graph & Netlist Specification

## Overview
In **Project NETLIST**, the circuit graph is not merely a visual display; it is the **central, machine-readable data structure** of the entire pipeline. 

To preserve exact electrical semantics without losing terminal identity, the system represents circuits as a **typed bipartite graph** (Components, Terminals, Nets) that can be seamlessly exported to NetworkX MultiGraphs and simulation-ready SPICE netlists.

---

## 1. Node Types & Attributes

### A. Component Nodes (`type="component"`)
Represents an individual physical or symbol component instance.

| Field | Type | Description | Example |
| :--- | :--- | :--- | :--- |
| `id` | `str` | Canonical component ID | `"R1"`, `"C1"`, `"Q1"`, `"V1"` |
| `type` | `str` | Class name from `classes.json` | `"resistor"`, `"transistor.bjt"` |
| `class_id` | `int` | Integer class index | `10` |
| `bbox` | `List[float]` | Absolute pixel bounding box `[xmin, ymin, xmax, ymax]` | `[352, 386, 384, 449]` |
| `center` | `Tuple[float, float]` | Bounding box center `(cx, cy)` | `(368.0, 417.5)` |
| `orientation` | `float` | Estimated rotation angle in degrees | `90.0` |
| `confidence` | `float` | Detection confidence score | `0.94` |
| `terminals` | `List[Terminal]` | List of attached component terminals | `[Terminal(id="T1"...)]` |

### B. Terminal Nodes (`type="terminal"`)
Represents an electrical pin/port belonging to a specific component.

| Field | Type | Description | Example |
| :--- | :--- | :--- | :--- |
| `id` | `str` | Local pin identifier | `"T1"`, `"T2"`, `"A"`, `"K"`, `"B"`, `"C"`, `"E"` |
| `semantic_name` | `str` | Pin function | `"anode"`, `"cathode"`, `"base"`, `"connector"` |
| `position` | `Tuple[float, float]` | Image coordinate `(x, y)` | `(368.0, 386.0)` |
| `connected_net` | `Optional[str]` | Assigned net ID | `"NET1"` |

### C. Net Nodes (`type="net"`)
Represents an equipotential electrical node connecting two or more component terminals.

| Field | Type | Description | Example |
| :--- | :--- | :--- | :--- |
| `id` | `str` | Canonical net ID (`"0"` for Ground) | `"NET1"`, `"NET2"`, `"0"` |
| `terminals` | `List[str]` | List of `"CompID.TermID"` references | `["R1.T2", "C1.T1", "D1.A"]` |

---

## 2. Graph Edges & Relations

1. **`HAS_TERMINAL` Edge**:
   $$\text{Component} \xrightarrow{\text{HAS\_TERMINAL}} \text{Terminal}$$
   Connects a component to its constituent terminals.

2. **`BELONGS_TO` Edge**:
   $$\text{Terminal} \xrightarrow{\text{BELONGS\_TO}} \text{Net}$$
   Connects a terminal pin to its electrical net.

---

## 3. Canonical Naming & Normalization Rules

To enable deterministic evaluation against ground truth, graphs undergo deterministic normalization:

1. **Component Relabeling**:
   - `resistor` $\rightarrow$ `R1, R2, R3...`
   - `capacitor` $\rightarrow$ `C1, C2, C3...`
   - `inductor` $\rightarrow$ `L1, L2...`
   - `diode` $\rightarrow$ `D1, D2...`
   - `transistor` $\rightarrow$ `Q1, Q2...`
   - `voltage` $\rightarrow$ `V1, V2...`
   - `integrated_circuit` $\rightarrow$ `U1, U2...`
   - `gnd` $\rightarrow$ `GND1, GND2...`

2. **Spatial Ordering**:
   Components are sorted by spatial reading order (top-to-bottom, left-to-right based on center coordinates) before re-indexing.

3. **Net Relabeling**:
   - Nets containing Ground terminals are assigned `id = "0"`.
   - Other nets are sorted by their lexicographically smallest terminal reference and labeled `NET1, NET2, NET3...`.

## 4. JSON Serialization Format

```json
{
  "components": [
    {
      "id": "R1",
      "type": "resistor",
      "class_id": 10,
      "bbox": [352.0, 386.0, 384.0, 449.0],
      "center": [368.0, 417.5],
      "orientation": 90.0,
      "terminals": [
        {
          "id": "T1",
          "semantic_name": "connector",
          "position": [368.0, 386.0],
          "net": "NET1"
        },
        {
          "id": "T2",
          "semantic_name": "connector",
          "position": [368.0, 449.0],
          "net": "NET2"
        }
      ]
    }
  ],
  "nets": {
    "NET1": ["R1.T1", "V1.POS"],
    "NET2": ["R1.T2", "C1.T1"],
    "0": ["C1.T2", "V1.NEG"]
  },
  "metadata": {
    "source_image": "C1_D1_P1.jpg"
  }
}
```
